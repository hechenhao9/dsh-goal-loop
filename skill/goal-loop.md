# 目标工程 · 三层闸门（机器 / 评审 / 校准）

> 前两层是「双层闸门」，第三层校准守的是标准本身准不准。三层都过才叫交付。

## 一句话

**能不能交，不由我说。** 机器能判的写成命令跑一遍，机器判不了的交给没参与动手的人按事先写好的标准打分，标准准不准由押注与对账守着；三层都过才许开口说"完成"。

## 三代分界：判断权归谁

| 代 | 做法 | 谁在判 |
|---|---|---|
| 提示词工程 | 把话说漂亮、加约束、加例子 | 我，凭感觉 |
| 上下文工程 | 把料给全：文件、历史、工具 | 我，凭更全的感觉 |
| **目标工程** | 把"要什么结果"写成可验的判据，然后循环到判据全过 | **判据本身**，不是我 |

差别只在这一处：**前两代我既当选手又当裁判，这一代裁判席上是别人写的东西。**

## 一份合约，两层闸门

合约落在 `.goal/<id>/goal.json`，两层写在同一个文件里——因为"这份东西算不算做到"本来就是一个问题的两面。

| | 机器层 `done_when` | 评审层 `rubric` |
|---|---|---|
| 判据形态 | 一条能真跑的命令，退出码/输出就是答案 | 一句人话判据 + 正反例 + 权重 |
| 谁来判 | 机器 | 没参与动手的独立一方 |
| 不过怎么办 | 修，重跑，直到全绿 | 只改扣分那几处，重新判 |
| 能不能糊弄 | 糊弄不了（跑不出来就是跑不出来） | 能糊弄，所以机器替人审计判分过程 |

**分歧线是一句话：换个人只靠这条命令，能不能判真假？**
- 能 → 机器层。`node --test` 退出码 0、文件存在、接口返回 200、`grep` 得到那一行。
- 不能 → 评审层。"这份报告能不能让老板直接转发"、"这个价位的客户会不会觉得贵"。
- **硬要写成命令的软判据，会变成假绿灯**：`grep -c "综上" > 0` 能过，但没人会因此觉得写得好。

## 动手之前必须落的四件事

`goal_define` 一次落全，落不下就没有开工资格：

1. **objective** — 交付什么、给谁用、什么规模。低于 12 字会被拒收。
2. **done_when** — 每条一个能真跑的命令。写不出命令的那条，说明还没想清什么叫做到。
3. **non_goals** — 明确不做什么。这是挡住"顺便把别的也改了"的唯一装置。
4. **rubric**（判不了好坏时才有）— 4–6 维、权重合计 100、每维有正反例、至少一条红线。

合约被拒收不是障碍，是**目标还不可验收**的信号。补全再落，不许"先干着看"。

## done_when 的写法

唯一标准：**换个人、换台机器、只看这一条，他能自己判真假吗？**

- 好：`node --test test/*.test.mjs` + `expect: {kind: 'exit', value: 0}`
- 好：`curl -s localhost:8080/health` + `{kind: 'contains', value: '"ok":true'}`
- 坏：`检查一下代码质量`（没有命令，也没有阈值）
- 坏：`确认功能正常`（"正常"是谁的标准？）
- 允许 `manual`，但**全部 manual 会被拒收**——那就等于没有机器层，退化成"我说了算"。

## rubric 的写法（判不了好坏时）

每一维必须能通过这个自检：**单独发给一个只看过题目、没看过稿子的人，他能否明白为什么这一条必须存在。**

- `criterion` ≥12 字，且必须含**可被外部抽查**的东西：路径、文件名、行号、数字、命令、原文片段。
  - 好：`README 的安装段必须给出能直接粘贴的一条命令，且该命令与 install.ps1 实际接受的参数一致`
  - 坏：`文档要清晰完整`（清晰是谁的清晰）
- `pass_example` / `fail_example` 各 ≥8 字且不能相同——正反例一样，等于没说清界线。
- `intent`（这条防的是哪种稿子）+ `vision`（满分长什么样）：这两项是给动手的人看的，不是给我看的。
- 权重：**会直接害人**（编数据、错口径）25–30 并配红线；**会让对方做错动作**（模糊、不可执行）20–25；**只是不漂亮**（语气、排版）10–15。四维各 25 = 还没想清楚。
- 红线 `vetoes` 至少一条，每条 why ≥10 字。命中就不许交，**不看分数**。
- 合格线默认 95：95 = 发出去不会被问倒；再往上 5 分花在没人看的地方。

## 谁不能给谁判分

| 角色 | 做什么 | 绝对不做 |
|---|---|---|
| 教授（`goal-professor`） | 只读题目与素材，写 rubric | 不许看任何稿、不许示范写法、不许按"我想要的效果"反推判据 |
| 导师（`goal-tutor`） | 按 rubric 把稿子做到过线 | 不许改 rubric、不许自加判据、不许问"怎么写才能过" |
| 判分人（`goal-reviewer`） | 给每一维打分、抄原文当证据 | **不能是写稿的人**；`reviewer: "self"` 会被机器直接拒收 |

拆开只解决一件事：**写标准的人不能是写稿的人。**
出题人和考生同一个人时，标准里会不知不觉印着稿子的特征（词数区间、喜欢的句式、能整段复制的段落），那个满分是自盖章。

## 第三层：押注与对账（尺子准不准）

前两层验的是"东西对不对"，这一层验的是**标准准不准**。没有它，一个偏松的 rubric 会让你连续十次报满分，而每次都很自信。

1. **判分前先押注**（`goal_predict`）：每维押 0/4/7/10，加总分区间与依据（≥12 字）。
2. **落盘即封**：写进去就带 digest，改不了。看到分数再补预测等于抄答案——机器按轮次比时间戳，判过分之后补的预测直接拒收（`PREDICT_AFTER_REVIEW`）。
3. **押注人不能是判分人**：同一个名字出现在两边，`goal_review` 当场拒收。换一个人押，或者换一个人判。
4. **判完对账**（`goal_retro`）：逐维 `delta = 实际 − 押注`。`delta < 0` 是**高估**（尺子把稿子想得比实际好），`> 0` 是**低估**。
5. **连续 3 轮同向 = 错的是标准不是稿子**：改 `criterion`，并给 `rubric_change_reason`。旧判分会被标 `stale`（不删——删了这次偏差就等于没发生过）。
6. **换尺子必须有理由**：改 rubric 却不给理由，`goal_define` 拒收；删维必须解释。

**本插件不做的一件事**：不替你重判历史样本。标了 stale 之后要不要重打分由你决定——机器只保证新分不会被当成和旧分可比。

## 红灯驱动循环

1. `goal_check` 跑机器层 → 只修红灯列出的那几条，**修完必须重跑**（上一轮的绿不作数）。
2. 机器层全绿后，独立判分人按 rubric 打分 → `goal_review` 提交 → 机器审计（引文逐字对、分数重算、扣分要能落成改法）。审计不过就改判分本身，别急着改稿。
3. 判完 `goal_retro` 对账 → 连续偏差到 3 轮就动标准，不动稿子。
4. 改稿时**只动扣分那几处，且每轮至少删掉一处**——只加不减会长成 AI 腔。
5. 说"完成"之前 `goal_verdict`，`deliverable: true` 才许汇报。

预算：默认 5 轮 / 90 分钟。**第三轮还过不去，问题在标准不在稿**——改 criterion，不要继续改稿。超预算就写 `BLOCKED.md`：卡在哪一维、当前几分、需要对方给什么、不给时停在哪。

## 不必建合约的三类

- 纯问答：问一句答一句。
- 单点排错：报错 → 根因 → 修法 → 复验，本身就是闭环。
- 闲聊、探索、找方向。

**为建合约而建合约是第四代错误**：把一句"帮我看看这个"变成五条验收，比不建更糟。

## 反模式清单

- 把 `done_when` 写成"检查是否完成"——这是在用需求复述需求。
- rubric 里写"要专业、要完整、要有深度"——不可抽查，判分只能凭印象。
- 分数给 8.5 分——档位只有 0/4/7/10，精确到小数是假精确。
- 扣分只说"这段不够好"——必须是「把 `draft-v2.md:63` 的「原文」改成「新句」」。
- 自己写稿自己判分，然后报 100 分。
- 机器层红了照样汇报完成，理由是"评审层 96 分"。
- 判分没过就把 rubric 改松——改的是标准，不是东西。
- 先看到分数，再回头补一份"预测"——那是抄答案，不是校准。
- 连续偏高就把合格线从 95 降到 90、把阈值从 4/5 降到 3/5 让这次过——改阈值本身是元层级的改动，要单独走理由和复核。
